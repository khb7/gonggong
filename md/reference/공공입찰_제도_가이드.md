## 1. 전체 흐름 한눈에

```
[발주처]                                    [입찰자]
추정가격 산정
   ↓
기초금액 공개 (공고)  ─────────────────────→  공고 확인
   ↓
복수예비가격 15개 생성 (비공개)                투찰 시 번호 2개 선택
   ↓                                          투찰금액 제출
개찰
   ↓
가장 많이 선택된 번호 4개 평균 → 예정가격 확정
   ↓
낙찰하한가 = f(예정가격, 낙찰하한율, A값)
   ↓
하한가 이상 + 예정가격 이하 중 최저가 순으로
적격심사 → 95점 이상이면 낙찰
```

## 2. 가격 용어 체계

발주처가 만드는 금액과 입찰자가 계산하는 금액이 층층이 다르다. 이걸 헷갈리면 전부 틀린다.

| 용어 | 정의 | 공개 여부 | 우리 DB 컬럼 |
|------|------|----------|-------------|
| **추정가격** | 부가세·관급자재 제외한 순수 공사비 추정치. **입찰 방식·하한율 구간을 가르는 기준** | 공고 | — |
| **추정금액** | 추정가격 + 부가세 + 관급자재비 | 공고 | — |
| **기초금액** | 발주처가 산정·공개하는 예정가격 기준선 | ✅ 공개 | `base_price` |
| **복수예비가격** | 기초금액 ±2~3% 범위의 서로 다른 15개 가격 | ❌ 개찰 전 비공개 | — |
| **예정가격** | 개찰 시 확정되는 실제 기준가. 15개 중 4개 평균 | ❌ → 개찰 후 공개 | `expected_price` |
| **사정률** | 예정가격 ÷ 기초금액. 사실상 **제도가 만들어내는 난수** | 개찰 후 | `adjustment_rate` |
| **낙찰하한율** | 예정가격 대비 투찰 가능한 최저 비율 | ✅ 공고 | `lower_limit_rate` |
| **낙찰하한가** | 실제 커트라인 금액 | 개찰 후 계산 | — |
| **투찰율** | 투찰금액 ÷ 예정가격 | 개찰 후 | `bid_rate` |
| **A값** | 투찰율 적용에서 **제외**되는 법정경비 | 공고 | ❌ 미수집 |

> **주의**: 업계에서 "투찰율"이라 할 때 *기초금액 대비*를 뜻하는 경우와 *예정가격 대비*를 뜻하는 경우가 섞여 있다.
> 정보21c CSV의 `투찰율`이 어느 쪽 기준인지는 `md/data/data_quality_fixes.md`에서 검증한 값을 따른다.

## 3. 예정가격 결정 메커니즘 (복수예가)

2004년 이전 밀봉입찰이 담합으로 무너진 뒤 도입된 구조다. **아무도 예정가격을 미리 알 수 없게** 만드는 것이 설계 목적이다.

1. 발주처가 기초금액을 중심으로 **15개**의 복수예비가격을 생성한다.
   - **국가계약: 기초금액 ±2%** → 사정률 이론 범위 **98~102%**
   - **지방계약: 기초금액 ±3%** → 사정률 이론 범위 **97~103%**
   - 통상 100% 미만 7개 / 100% 초과 8개로 분포
2. 입찰자는 투찰할 때 15개 번호 중 **2개**를 고른다 (금액은 모름).
3. 개찰 시 **가장 많이 선택된 번호 4개**의 산술평균 = 예정가격.

### 이게 이 프로젝트에 갖는 의미

- 우리 주 타겟인 **지자체·교육청 발주는 지방계약** → ±3% → 사정률 분포가 국가계약보다 **넓다**.
  회의록(26.03.27)의 "기존 97~103% 범위" 발언은 이 지방계약 ±3%와 정확히 일치한다.
- **국가계약(국방부 등)과 지방계약 데이터를 한 통계에 섞으면 분산이 오염된다.**
  현재 `bids_history`에 계약 근거법(국가/지방) 구분 컬럼이 없다. → [10장 TODO](#10-이-프로젝트에서-확인해야-할-것)
- 사정률은 "발주처 담당자의 습관"이 아니라 **다수 입찰자의 번호 선택 결과**다.
  즉 예측 대상이 아니라 **경쟁자 집단행동의 산물**이다. 이것이 프로젝트가 사정률 예측을 폐기하고
  분포 기반 의사결정으로 전환한 근거이며, `CLAUDE.md`의 "사정률 예측 강화 금지" 원칙과 같은 얘기다.

## 4. 낙찰자 결정 방식

우리가 다루는 실내건축(0002)·조경식재(0023)는 **거의 전부 적격심사**다. 다른 방식이 섞이면 분포가 깨진다.

| 방식 | 대상 | 특징 |
|------|------|------|
| **적격심사** | 추정가격 100억 미만 공사 | 예정가격 이하 최저가 순으로 심사, **95점 이상**이면 낙찰. ← **우리 타겟** |
| **종합심사낙찰제** | 추정가격 100억 이상 공사 | 가격 + 공사수행능력 + 사회적책임 종합 |
| **협상에 의한 계약** | 용역 다수 | 기술평가 비중 큼. 가격 분포 무의미 |
| **최저가 / 제한적 최저가** | — | 하한율 구조가 다름 |

### 적격심사의 실질

- 심사 통과선 95점은 **면허·실적·경영상태가 정상이면 대부분 통과**한다.
- 따라서 실질적으로 **"낙찰하한가 이상 중 최저가"** 게임이 된다.
- → 낙찰하한가에 얼마나 가깝게 붙이느냐가 전부다. 이것이 등수 안정화가 목표인 이유.

## 6. A값 (법정경비) — 현재 미반영

적격심사 투찰금액 산식은 단순 곱셈이 아니다.

```
낙찰하한가 = (예정가격 − A값) × 낙찰하한율 + A값
```

**A값 구성** (투찰율 적용에서 제외되는 7개 항목):
국민연금, 건강보험, 노인장기요양보험, 퇴직공제부금비, 산업안전보건관리비, 안전관리비, 품질관리비

- A값을 제외하지 않고 하한율을 곱하면 **실제 하한가보다 낮게 써서 부적격 탈락**한다.
- 2026년 1월 30일부터 소액수의계약 견적 제출에도 A값 제외 규정이 적용된다.
- **적용 범위**: 정보21c 안내문은 "시설공사 **일부** 적격심사에 한하여"라고 쓰지만,
  실측 결과 **일부가 아니다**. 아래 참조.

### 📊 실측: A값은 예외가 아니라 기본값이다 (2026-08-27 검증)

`data/downloads/info21c_0002_20250501_20250515.xlsx` (건축공사업 0002, 2025-05-01~15, 81건) 분석 결과:

| 항목 | 결과 |
|------|------|
| 전체 공고 | 81건 |
| **공고명에 `[A값]` 태그** | **57건 (70%)** |
| A값 비중 (예정가격 대비) | 평균 **3.71%**, 범위 0~13.7% |

**즉 A값을 무시하면 대부분의 공고에서 하한가 미달로 탈락한다.**
A/예가 3.7%, 법정 하한율 88%면 실효 하한율은 **88.35%** — 0.35%p 차이다.
등수가 소수점 셋째 자리에서 갈리는 게임에서 0.35%p는 경쟁권 밖이다.

#### ⭐ 정보21c `입찰리스트` 엑셀 — A값을 역산할 수 있다

A값 **금액 컬럼은 없다**. 하지만 두 가지가 들어 있어서 계산이 된다.

`data/downloads/info21c_0002_20250501_20250515.xlsx` / 시트 `입찰리스트` (20개 컬럼):

```
번호 | 공고명 | 공고번호 | 발주기관 | 기초금액 | 예정가격 | 1순위투찰금액 | 1순위기초대비
| 1순위업체 | 1순위사업자번호 | 예가/기초(100%) | 예가/기초(0%) | 개찰일 | 업종 | 지역
| 낙찰하한가 | 업체수 | 1순위사정율(100%) | 1순위사정율(0%) | G2B물품분류
```

**1. `공고명`의 `[A값]` 태그 = 적용 여부 플래그**
정보21c가 공고명 뒤에 태그를 붙인다: `[급][제한][A값][순]`, `[관내][수의][기초][A값]` 등.
→ 별도 컬럼 없이 문자열 매칭으로 A값 적용 여부를 판별할 수 있다.

**2. `낙찰하한가` + `예정가격` = A값 역산**

```
낙찰하한가 = (예정가격 − A) × r + A          (r = 법정 낙찰하한율)
  ⇒  A = (낙찰하한가 − 예정가격 × r) / (1 − r)
```

**검증 결과** — 이 역산이 실제로 맞는지 81건으로 확인했다:

| 구분 | 역산된 A값 |
|------|-----------|
| `[A값]` 태그 **없는** 건 (n=7) | **0 ~ 7원** (사실상 정확히 0) |
| `[A값]` 태그 **있는** 건 (n=49) | 예정가격의 평균 **3.71%** (0.08% ~ 13.73%) |

태그 없는 건이 전부 0으로 떨어진다는 건 **공식과 데이터가 둘 다 맞다는 뜻**이다.

실제 예 — `학생회관 승강기 설치 공사 [제한][A값][순]`:
```
예정가격    328,577,900
낙찰하한가  289,985,144       → 하한가/예가 = 0.88255
법정 하한율 0.88              → A = 6,971,600 (예가의 2.12%)
```
A값을 무시하고 `예정가격 × 0.88`로 계산하면 289,148,552원 → **하한가보다 836,592원 낮아 부적격 탈락**.

**⚠️ 단, 큰 건에는 `낙찰하한가`가 비어 있다.** LH 아파트 공사(예가 900억~1,800억, 종합심사낙찰제) 6건은
`[A값]` 태그는 있지만 `낙찰하한가` 칸이 비었다. 적격심사 건에만 채워진다 — 우리 타겟 구간은 문제없다.

#### ⚠️ `lower_limit_rate` 컬럼의 의미가 소스마다 다르다

[scripts/etl_csv.py:178-182](scripts/etl_csv.py#L178)가 이렇게 동작한다:

```python
# 낙찰하한가 컬럼 있으면 낙찰하한가/예정가격으로 계산
if raw_llh ...:
    lower_limit = float(raw_llh) / est_price     # ← A값이 녹아든 '실효 하한율'
```

즉 `bids_history.lower_limit_rate`에는 **두 가지 의미가 섞여 있다**:
- 낙찰하한가 컬럼이 있던 행 → **실효 하한율** (A값 포함)
- 없던 행 / G2B 수집분 → **법정 하한율** (A값 제외)

현재 DB 실측(467건, 71개 distinct): 대부분은 법정값(0.87745 173건, 0.86745 101건, 0.89745 50건 …)이고
0.88429·0.90313·0.90371 같은 어중간한 값 소수가 실효 하한율이다.
→ **두 의미를 분리한 컬럼이 필요하다.** 안 그러면 분포 정규화 기준이 행마다 달라진다.

#### 🔑 나라장터 입찰공고정보서비스 — 활용신청이 필요하다

A값이 API로 나온다면 여기다. 이 서비스는 **기초금액정보 / 입찰공고상세정보 / 면허제한정보 / 참가가능지역정보**를
업무구분(물품·용역·공사·외자)별 오퍼레이션으로 제공한다. 우리가 지금 쓰는 개방표준서비스와 **다른 서비스**다.

- 신청: [공공데이터포털 15129394 — 조달청_나라장터 입찰공고정보서비스](https://www.data.go.kr/data/15129394/openapi.do)
- 공사 기초금액: `https://apis.data.go.kr/1230000/ad/BidPublicInfoService/getBidPblancListInfoCnstwkBsisAmount`
- **현재 키 상태 (실측)**: 위 엔드포인트 호출 시 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` (코드 30) 반환.
  존재하지 않는 서비스 오류(코드 12)가 아니라 **경로는 유효하고 키만 미등록**이라는 뜻이다.
  → 현재 `.env`의 `G2B_API_KEY`는 개방표준서비스에만 등록되어 있다. **활용신청 후 재확인.**
- 승인 후 확인할 것: 응답에 안전관리비·품질관리비·국민연금·건강보험·퇴직공제·노인장기요양 항목이 실제로 오는지.
  오면 A값 = 해당 항목 합계로 계산 가능. 안 오면 공고 원문 파싱 외에 방법이 없다.

> 참고: 지역제한 여부(`rgnLmtYn`)·면허제한 정보도 같은 서비스에 있다. 한 번 신청하면 [10장](#10-이-프로젝트에서-확인해야-할-것)의 여러 TODO가 같이 풀린다.

### ⚠️ 프로젝트 영향

현재 투찰가 공식 `base_price × predicted_rate × (LLR + offset)`에는 **A값이 없다**.
A값이 0이 아닌 공고에서는 이 공식이 실제 하한가와 어긋난다. A값 비중이 클수록 오차가 커진다.
`bids_history`에 A값 컬럼도, 수집 경로도 없다. → [10장 TODO](#10-이-프로젝트에서-확인해야-할-것)

## 7. 국가계약 vs 지방계약

| | 국가계약 | 지방계약 |
|---|---------|---------|
| 근거법 | 국가를 당사자로 하는 계약에 관한 법률 | 지방자치단체를 당사자로 하는 계약에 관한 법률 |
| 소관 | 기획재정부 / 조달청 | 행정안전부 |
| 발주처 예시 | 국방부, 중앙부처, 공공기관 | 시·도·군·구, 시도교육청 |
| **복수예가 범위** | **±2%** | **±3%** |
| 하한율 상향 시행 | 2026-01-30 | 2025-07-08 |

> 두 체계는 **사정률 분산 자체가 다르다**. 발주처별 통계를 낼 때 이 구분이 지역·발주처보다 상위 분리축이어야 한다.

## 8. 입찰 참가 제한

### 면허(업종) 제한
- `면허업종제한목록` 필드로 표현. 우리 관심 코드: **`0002` 건축공사업**, **`0023` 조경식재공사업**
- 공사업 면허는 기술자 보유 요건이 있어 진입장벽이 있다 → 용역(위생·소독 등)보다 경쟁자 수가 적다

### ⚠️ 시설물유지관리업 통폐합 (2026년 완료)
- 시설물유지관리업 면허가 **건축공사업 등으로 통폐합**되는 절차가 2026년에 종료된다
- 경기도 기준 기존 건축 경쟁업체에 시설물 업체가 합류 → **경쟁업체 1,400개 이상**으로 급증
- **2026년 이후 데이터는 참가자 수 분포가 구조적으로 이동한다.** 과거 데이터를 그대로 쓰면 안 된다

### 지역 제한
- `rgnLmtYn` / `지역제한코드목록`. 해당 지역 본점 업체만 참가 가능 → 참가자 수가 크게 줄어든다
- 지역제한 유무는 **경쟁 강도를 가르는 1차 변수**다. 분포 통계에서 반드시 분리해야 한다

### 공동수급(공동도급)
- 지역업체 의무 참여 비율이 붙는 공고가 있다. 실질 경쟁자 수 해석이 달라진다

## 10. 이 프로젝트에서 확인해야 할 것

- [x] **하한율 하드코딩 제거** — 2026-08-27 완료. 5장 표 참고. "값 없으면 실패" 원칙으로 통일
- [ ] **`lower_limit_rate` 개정일 경계 검증** — 분포 자체는 [validate_data.py](scripts/validate_data.py)가 출력한다
      (0.87745:5935 / 0.88:486 / 0.87995:270 …). 남은 것은 **2025-07-08 전후로 실제로 갈리는지** 날짜별 확인
- [ ] **계약 근거법 컬럼 추가** — 수요기관명으로 국가/지방 판별 가능한지 먼저 조사

- [x] **⭐ A값 파이프라인 구축** — 2026-08-27 완료. [app/engine/a_value.py](app/engine/a_value.py), 마이그레이션 `d5c7b39a4e10`,
