# 설계 문서: 데이터 재수집 및 품질 검증 계획

**작성일:** 2026-04-04
**배경:** 기존 bids_history 2,267건이 요약 포맷으로 수집되어 핵심 컬럼이 손상된 상태. 상세 포맷으로 재수집 필요.

---

## 문제 현황

| 컬럼 | 상태 | 엔진 영향 |
|------|------|-----------|
| `adjustment_rate` | ✅ 정상 (97~102%) | 사정률 예측 — 정상 |
| `client_name` | ✅ 정상 | Fallback Level 1 — 정상 |
| `region` | ❌ 기관명 2글자로 잘림 | Fallback Level 2 — 망가짐 |
| `lower_limit_rate` | ❌ 전체 0.87745 고정 | 투찰가 계산 — 망가짐 |
| `participants` | ❌ 전체 0 | 현재 미사용 (전략 aggressive 고정) |
| `price_method` | ❌ 전체 '기타' | 통계 왜곡 가능성 |

**원인:** Info21c 낙찰현황 **요약 포맷** 다운로드. 낙찰하한율·입찰참여자수·수요기관지역 컬럼 부재.
**해결:** Info21c **상세 포맷** (개찰결과 상세) 으로 재수집.

---

## 접근 방식

`--debug` 모드 수동 확인 → ETL 검증 → 자동 백필

- 다운로더 자체는 동작 확인됨. 내보내기 시 컬럼 선택이 문제였음.
- 첫 1회만 `--debug`로 수동 확인, 이후 `backfill_info21c.py`로 자동화.

---

## 섹션 1: 전체 흐름

```
Phase 1 — 테스트 (2025년)
  Step 1. TRUNCATE bids_history
  Step 2. --debug 모드로 2025년 1월 소량 다운로드 (1개월)
           → 내보내기 다이얼로그에서 컬럼 선택 직접 확인
           → CSV 첫 행 헤더 눈으로 검증
  Step 3. etl_csv.py 실행
  Step 4. validate_data.py 실행 → 품질 기준 통과 확인
  Step 5. backfill_info21c.py --start 2025 --end 2026 (자동)

Phase 2 — 확장 (Phase 1 통과 후)
  Step 6. backfill_info21c.py --start 2023 --end 2024
```

## 섹션 2: ETL 수정 — price_method 태깅

### 우선순위

1. **Info21c 상세 포맷에 `예정가격결정방식` 컬럼이 있으면** → 직접 매핑
   - `복수예비가격` → `"복수예비가격"`
   - `고정예정가격` → `"고정예정가격"`
   - 나머지 → `"기타"`

2. **컬럼이 없으면** → 일단 구분 없이 `"기타"` 유지하고 진행
   - 적재 후 validate_data.py 에서 adjustment_rate=1.000 비율 확인
   - 비율이 높아 통계 왜곡이 실제로 보이면 그때 휴리스틱 추가 결정
   - 휴리스틱 후보: `abs(adjustment_rate - 1.0) < 0.001` → `"고정예정가격 추정"`

### 왜 미리 만들지 않는가

- 복수예비가격도 랜덤하게 1.000 근처에 떨어질 수 있어 오분류 발생 가능
- 컬럼 유무를 먼저 확인하는 게 선행. 없을 때 휴리스틱을 쓸지는 실제 데이터 보고 결정

## 섹션 3: 데이터 품질 검증 스크립트 (`scripts/validate_data.py`)

ETL 실행 후 자동으로 통과/실패를 판정하는 스크립트.

### 검증 항목 및 기준

| 항목 | 경고 기준 | 실패 기준 |
|------|----------|----------|
| `participants` 분포 | 0이 30% 이상 | 0이 80% 이상 |
| `lower_limit_rate` 단일값 비율 | 0.87745 고정이 50% 이상 | 90% 이상 |
| `region` 의심값 비율 | 알려진 지역명 화이트리스트 외 값이 20% 이상 | 50% 이상 |
| `price_method` 분포 | — | 출력만 (판정 없음) |
| `adjustment_rate` 범위 | 0.95 미만 또는 1.05 초과가 1% 이상 | 5% 이상 |

### 추가 출력

- 상위 발주처 10개에 대해 예상 fallback_level 시뮬레이션 (20건 기준)
- region 화이트리스트: 경기, 서울, 인천, 부산, 대구, 대전, 광주, 울산, 세종, 강원, 충남, 충북, 전남, 전북, 경남, 경북, 제주, 전국 및 이들의 조합 (예: 전국,경기)
- adjustment_rate 히스토그램 (97~103% 구간)
- 총 적재 건수 / 공종별 / 버킷별 분포

### 판정 로직

```
실패 항목 0개 → "✅ 백필 진행 가능"
실패 항목 1개 이상 → "❌ 원인 파악 후 재수집 필요"
경고만 있으면 → "⚠ 진행 가능하나 데이터 품질 주의"
```

## 섹션 4: 내보내기 컬럼 선택 체크리스트

`--debug` 모드 실행 시 내보내기 다이얼로그에서 확인할 항목:

### 필수 컬럼 (없으면 ETL 실패)

- [ ] 입찰공고번호
- [ ] 개찰순위
- [ ] 면허업종제한목록
- [ ] **낙찰하한율** ← 요약 포맷에서 빠진 핵심
- [ ] 기초금액
- [ ] 예산가격
- [ ] 투찰금액
- [ ] **입찰참여자수** ← 요약 포맷에서 빠진 핵심

### 있으면 좋은 컬럼

- [ ] 투찰일자 → bid_date
- [ ] 낙찰방법 → bid_type
- [ ] 수요기관 → client_name
- [ ] **수요기관지역** → region ← 요약 포맷에서 잘렸던 핵심
- [ ] 수요기관사업자등록번호 → client_id
- [ ] **예정가격결정방식** → price_method ← 있으면 바로 매핑

### 내보내기 옵션

| 옵션 | 설정값 |
|------|--------|
| 파일 형식 | CSV |
| 구분자 | `,` (쉼표) |
| 리포트 제목 내보내기 | **OFF** |
| 필터 세부사항 내보내기 | **OFF** |
| 추가 열 제거 | ON |

- 2023~2026 실내건축 + 조경 전체 적재
- 단골 발주처 (국방부, 교육청, 경기도 지자체) fallback_level `"client"` 안정 확보
- confidence_grade `"high"` 발주처 5개 이상
