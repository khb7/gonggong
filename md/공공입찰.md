# Phase 1 (MVP): Robust Statistical Bidding Model (요약)

> AI 없이도 입찰 데이터의 노이즈를 제거하고 정확한 투찰 타점을 계산하는 통계 기반 엔진.

---

## 1. 데이터 분리 (Data Isolation)
입찰 데이터는 혼합 분포(Mixture Distribution) 형태이므로 그대로 평균을 쓰면 정확도가 떨어집니다. 따라서 데이터를 다음 기준으로 철저히 분리하여 분석합니다.

### 1️⃣ 공종 분리
* 실내건축
* 조경
* *(주의: 다른 공종 데이터 혼합 절대 금지)*

### 2️⃣ 금액 구간 분리 (Size Bucketing)


| 구간 | 특징 |
| :--- | :--- |
| **< 1억** | 초정밀 소수점 경쟁 |
| **1억 ~ 5억** | 표준 경쟁 |
| **5억 ~ 20억** | 중형 경쟁 |
| **20억 이상** | 보수적 투찰 |

---

## 2. 발주처 패턴 모델 (Issuer Pattern Model)
기관마다 사정률 패턴(난수 생성 습관)이 다릅니다. 따라서 전체 평균이 아닌 기관별 통계를 최우선으로 사용합니다.

**예시: 기관별 사정률 차이**
| 기관 | 평균 사정률 |
| :--- | :--- |
| 지자체 | 1.002 |
| 교육청 | 1.000 |
| 공기업 | 0.998 |

**계층적 Fallback 구조 (데이터 부족 시 대안)**
1.  **발주처:** 데이터 ≥ 20건일 경우 최우선 사용
2.  **지역:** 발주처 데이터 부족 시 사용
3.  **공종 + 금액:** 지역 데이터도 부족할 경우 사용
4.  **전체 데이터:** 최후의 수단

---

## 3. 극단값 제거 (Trimmed Median)
입찰 데이터에는 `0`을 하나 더 입력하거나 비정상적인 저가 투찰을 하는 등의 노이즈(Outlier)가 반드시 존재합니다.

* **해결책:** 상위 5%와 하위 5%를 제거한 후 중앙값을 계산하는 **Trimmed Median** 적용.
* **효과:** 실제 사정률의 순수한 중심값 도출 가능.

---

## 4. 분산 계산 (MAD)
표준편차(SD) 대신 극단값의 영향을 최소화하는 **MAD(Median Absolute Deviation)**를 사용합니다. 통계적으로 가장 안정적인 분산 측정 방식입니다.

* **신뢰 범위 (Range) 산출:**
    $$\text{Range}=[\text{Median}-\text{MAD},\text{Median}+\text{MAD}]$$

---

## 5. 오프셋 범위 (Offset Range)
단일 오프셋(고정값)을 사용하면 다른 투찰 프로그램들과 타점이 겹쳐 동가(Tie) 탈락 위험이 증가합니다. 이를 방지하기 위해 미세한 분산이 적용된 **범위형 오프셋**을 사용합니다.

* **Offset Candidates 예시:**
    * $\text{Median}-0.001$
    * $\text{Median}$
    * $\text{Median}+0.001$

---

## 6. 경쟁자 기반 동적 룰 (Competitor Count Rule)
참여 업체 수에 따라 적용할 Offset 전략(마진)을 동적으로 변경합니다.

| 경쟁자 수 | 적용 전략 | 투찰 행동 |
| :--- | :--- | :--- |
| **< 50명** | **Safe** | 동가 위험이 적으므로 마진 크게 |
| **50 ~ 150명** | **Normal** | 기본 궤적 추종 |
| **300명 이상** | **Aggressive** | 군집 형성되므로 마진 최소화하여 하단 타격 |

---

## 7. 전략 모드 (Strategy Mode)

* 🛡️ **Safe Bid:** $\text{Median}+\text{MAD}$
    * 목적: 안정적인 마진 확보 및 예가 초과 완벽 방지.
* ⚔️ **Aggressive Bid:** $\text{Median}-\text{MAD} \sim \text{Median}$
    * 목적: 경쟁이 극심할 때 낙찰 확률 극대화를 위한 승부수.

---

## 8. Digit Filter (동가 회피)
사람이나 매크로가 습관적으로 많이 사용하는 '게으른 끝자리'를 타점에서 강제 배제합니다.

* **블랙리스트:** `.000`, `.500`, `.745`, `.777` 등
* **조치:** 산출된 타점이 위 숫자에 해당할 경우 인접한 안전 숫자로 자동 이동(Shift).

---

## 9. 최종 투찰 공식

> **이 모델의 핵심 목적은 `사정률(Adjustment Rate)`을 정확히 예측하는 것이다.**
> 사정률은 개찰 전까지 공개되지 않는 비밀 난수이며, 이를 예측해야만 예정가격을 추정하고 하한가 직전 타점을 노릴 수 있다.

위의 모든 통계적 보정을 거친 최종 투찰가 산출 공식입니다.

$$\text{Final Bid Price}=\text{Base Price}\times\underbrace{\text{Predicted Rate}}_{\text{모델이 예측}}\times(\underbrace{\text{Lower Limit Rate}}_{\text{API에서 수집}}+\text{Offset})$$

| 변수 | 공개 여부 | 출처 |
| :--- | :--- | :--- |
| **Base Price** (기초금액) | ✅ 공개 | 나라장터 공고 / API |
| **Lower Limit Rate** (하한율) | ✅ 공개 | API 수집 (≈ **87.745% 고정**) |
| **Predicted Rate** (사정률) | ❌ 비공개 | **이 모델이 예측하는 값** |
| **Offset** | — | 경쟁자 수 및 MAD 기반 전략값 |

---

## 10. 최종 프로세스 (Workflow)


입찰 공고 입력부터 타점 출력까지의 전체 시스템 흐름입니다.

1.  공종 및 금액 버킷 분리
2.  발주처 통계 선택 (Fallback 로직 적용)
3.  Trimmed Median 계산
4.  MAD 계산
5.  Offset Range 생성
6.  경쟁자 수 기반 전략 선택
7.  Bid Range(다중 타점 포트폴리오) 생성
8.  Digit Filter 적용 (위험 소수점 회피)
9.  **최종 투찰가 리스트 출력**
