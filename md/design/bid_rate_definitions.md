# 투찰률·낙찰하한율 기준 정의 (확정)

작성 2026-08-27. 근거: Info21c 참여자 원본 XLS 409개 (`G:/내 드라이브/gonggong/participants/`) 전수 검증.

## 1. 원본 컬럼의 실제 의미

참여자 XLS 데이터 섹션 헤더 원문:

```
[0]순위 [1]등록번호 [3]업체명 [5]대표자 [6]투찰금액 [8]투찰율(%) [9]기초대비(%) [10]업체별사정율(%)
```

| 원본 컬럼 | 의미 | 저장 위치 | 상태 |
|---|---|---|---|
| `투찰율(%)` | **(투찰금액 − A) / (예정가격 − A)** | `bid_participants.bid_rate` | 정상 |
| `기초대비(%)` | 투찰금액 / **기초금액** | `bid_participants.base_rate` | 정상 |
| `업체별사정율(%)` | 업체별 사정률 | `bid_participants.vs_lower_limit` | **이름·주석 오류** |

### 투찰율은 A값이 제거된 조정 투찰율이다

A값이 0인 공고에서는 `투찰금액 / 예정가격` 과 값이 같아서 구분되지 않는다.
A값이 있는 공고에서만 차이가 드러난다.

검산 A — A값 없는 공고 (`20221202470-01`, 태영건설 1순위):
- 투찰금액 40,753,764,849 / 예정가격 48,361,508,925 = 0.84269 = 투찰율 84.269% ✓
- 투찰금액 40,753,764,849 / 기초금액 48,834,594,000 = 0.834526 = 기초대비 83.4526% ✓

검산 B — A값 9,949,086,054 인 공고 (`R26BK01359312-000`):
- 투찰금액 25,084,928,400 / 예정가격 28,098,535,925 = 0.892749 → 투찰율과 **불일치**
- (25,084,928,400 − A) / (28,098,535,925 − A) = 0.833956 = 투찰율 83.3955% ✓

**따라서 투찰율의 비교 기준선은 법정 낙찰하한율이다.** 실효 하한율
(= 낙찰하한가/예정가격)로 재면 A값이 이중 차감되어 분포가 왼쪽으로 밀린다.

실측 (낙찰자 불변식 위반, 하한율 갱신 완료된 223건):

| 기준선 | 위반 |
|---|---|
| `legal_limit_rate` | **0 / 223** |
| `effective_limit_rate` | 191 / 223 |

**`vs_lower_limit` 은 "낙찰하한율 대비 차이(%p)" 가 아니다.** 모델 주석
(`app/db/models.py` — "예비가격대비율 (낙찰하한율 기준 차이, %p)") 이 틀렸다.
실제로는 업체별 사정률이며, 값 범위가 0.98~1.00 이라 낙찰자에 대해 `>= 0` 검사가
무의미하게 통과한다. 이 컬럼으로 하한율을 역산하면 안 된다.

## 2. 낙찰하한가 산식 (확정)

```
낙찰하한가 = (예정가격 − A값) × 낙찰하한율 + A값
```

원본 409개 중 하한율·하한가·예정가격이 모두 있는 308개 전수 검증:

| 산식 | 일치 |
|---|---|
| `(예정가격 − A값) × 하한율 + A값` | 275 |
| `예정가격 × 하한율` (A값 = 0인 같은 식) | 33 |
| 설명 안 됨 | **0** |

A값은 관급자재·부가세 등 하한율 적용 대상에서 제외되는 금액이며,
참여자 XLS 의 `예정가격` 셀에 `"48,361,508,925 (A값: ...)"` 형태로 함께 들어온다.

### 따라 나오는 귀결

A값 > 0 이면 예정가격 대비 실효 임계 비율은 하한율보다 **높다**:

```
낙찰하한가 / 예정가격 = 하한율 + (A값 / 예정가격) × (1 − 하한율)
```

원본 `투찰율` 은 이 실효 비율이 아니라 **법정 하한율과 같은 축**의 값이다 (1절).
따라서 `투찰율 − 법정 하한율` 이 올바른 offset 이고, `투찰율 − 실효 하한율` 은 A값만큼 어긋난다.

## 3. 현재 엔진이 틀린 지점

`app/engine/distribution.py` 의 x축:

```python
offset = bid_rate - lower_limit_rate      # 투찰액/예정가격 − 하한율
```

문제는 기준선인 `lower_limit_rate` 값이 오염돼 있다는 것이다 (4절).
공고마다 x축이 제각각 밀려 있으므로 히스토그램 모양 자체가 무의미했다.

결과: 낙찰자 362건 중 **241건(66.6%)** 이 "낙찰하한율보다 낮게 투찰하고 낙찰됐다"는
물리적으로 불가능한 상태였다.

또한 A값 도입 시 기준선을 실효 하한율로 잡으면 A값이 이중 차감되어 더 나빠진다
(위반 66.6% → 70.7%). 기준선은 **법정** 하한율이어야 한다 (1절).

## 5. 확정: offset 은 법정 하한율 기준

```
offset = 투찰율 − 법정 낙찰하한율
       = bid_participants.bid_rate − bids_history.legal_limit_rate
```

투찰율이 이미 A값 조정을 거친 값이므로(1절) 별도 보정이 필요 없다.
불변식이 그대로 성립한다: **낙찰자 offset ≥ 0**.

> 초판에서 `offset = 투찰금액 / 낙찰하한가 − 1` 을 권고했으나, 검증에 쓴 표본이
> 전부 A값 0인 공고여서 투찰율의 A값 조정을 놓친 결과였다. 위 정의로 정정한다.

### 이 정의로 본 실제 낙찰자 분포 (하한율 갱신 완료 223건, DB 실측)

| 분위 | offset |
|---|---|
| p0 | +0.0000% |
| p5 | +0.0004% |
| p25 | +0.0013% |
| p50 | **+0.0046%** |
| p75 | +0.0405% |
| p95 | +1.9709% |
| p100 | +4.4571% |

**낙찰자 절반이 법정 하한율 +0.005% 이내에 붙어 있다.** 적격심사가 하한선에 최대한
붙이는 게임이라는 실무와 일치한다. 갱신 전 엔진이 그리던 `-0.6%` 피크(하한 미달 =
불가능)는 이 현실과 무관한 그림이었다.

갱신 후 분포 피크는 `+0.1% ~ +0.8%` 로 이동했고, 낙찰 27/40건이 `+0.1%` bin 에 몰린다.

bin 해상도는 후속 과제다. 현재 `_BIN_PCT_RESOLUTION = 1` (0.1% 단위) 로는
낙찰자 p25~p75 가 전부 한 bin 에 뭉친다. 다만 참여자 분포는 103개 bin 에 퍼지고
0.0% bin 쏠림이 3.2% 라, 막대그래프 자체가 깨지지는 않는다.

## 6. 확정된 정의 요약

```
기초대비율    = 투찰금액 / 기초금액
업체별사정율  = (원본 col10; 현재 vs_lower_limit 에 오명으로 저장)
사정률        = 예정가격 / 기초금액
낙찰하한가    = (예정가격 − A값) × 낙찰하한율 + A값
투찰율        = (투찰금액 − A값) / (예정가격 − A값)      ← A값 조정 완료
실효 하한율   = 낙찰하한가 / 예정가격                    ← 투찰율과 같은 축이 아님
offset        = 투찰율 − 법정 낙찰하한율
불변식        = 낙찰자 offset ≥ 0
```
