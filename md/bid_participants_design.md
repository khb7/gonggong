# bid_participants 테이블 설계

작성일: 2026-03-27

---

## 왜 만드는가

현재 `bids_history`는 **개찰순위 1위(낙찰자)** 데이터만 저장한다.
낙찰자의 사정률을 계산하는 데는 충분하지만, 아래 두 가지를 할 수 없다.

---

### 문제 1 — 경쟁 밀집 구간을 모른다

입찰에서 가장 위험한 상황은 **같은 금액 또는 극히 유사한 금액으로 여러 명이 겹치는 것**이다.
낙찰자 데이터만 있으면 이 상황이 얼마나 자주, 어떤 구간에서 발생하는지 알 수 없다.

```
예시: 기초금액 1억, 예정가격 9,910만원
  1위: 8,770,000원 (낙찰)
  2위: 8,770,000원 (동액 → 추첨 탈락)
  3위: 8,771,000원
  4위: 8,769,000원
  5위: 9,050,000원  ← 완전히 다른 전략
  ...
```

→ 전체 참여자 데이터가 없으면 "8,769~8,771만 원 구간에 4명이 몰렸다"는 걸 알 수 없다.
→ 현재 `digit_filter.py`의 블랙리스트는 경험칙 기반 정적 목록이다.
   데이터가 쌓이면 **발주처·공종별 실제 혼잡 끝자리**로 교체할 수 있다.

---

### 문제 2 — 업계 투찰 패턴을 모른다

같은 발주처·공종 과거 공고에서 전체 참여자 투찰율을 모으면
업계가 어느 구간에 집중하는지 분포가 보인다.

```
경기도교육청 실내건축 투찰율 분포 (전체 참여자 기준)
  0.877 ~ 0.880: ████████████ 41%  ← 과밀 구간
  0.880 ~ 0.890: ████ 14%
  0.890 ~ 0.900: ████████ 27%  ← 두 번째 집중 구간
  0.900 이상:    ██ 18%
```

→ "이 발주처에서는 0.877~0.880 구간이 과밀하니 살짝 벗어나는 전략이 유리"
   또는 "0.890 구간이 상대적으로 한산하니 여기서 정밀하게 노린다"는 판단 가능.

---

## 현재 구조와 한계

```
bids_history (현재)
  project_id  ← 공고 1개당 1행 (낙찰자만)
  adjustment_rate  ← 예정가격/기초금액 (사정률)
  winner_price     ← 낙찰자 투찰금액
  participants     ← 총 참여자 수 (숫자만, 각 투찰금액은 모름)
```

`participants = 15`라는 정보는 있지만,
나머지 14명이 얼마씩 냈는지는 전혀 알 수 없다.

---

## 신규 테이블 설계

```
bid_participants
  id          PK
  project_id  → bids_history.project_id (인덱스)
  rank        개찰순위 (1 = 낙찰자)
  bid_amount  투찰금액 (원)
  bid_rate    투찰율 = 투찰금액 / 예정가격 (소수)
  is_winner   낙찰자 여부 (rank == 1)

  UNIQUE(project_id, rank)
```

`bids_history`와의 관계:
```
bids_history.project_id  1 ──< bid_participants.project_id
```

공고 1개에 참여자 수만큼 행이 생긴다.
`bids_history`의 `adjustment_rate`(사정률)는 예정가격 기준이고,
`bid_participants`의 `bid_rate`(투찰율)는 각 참여자의 투찰금액/예정가격이다.
**두 개념은 다르다.**

---

## 데이터 수집 방법

조달청 데이터 허브에서 **개찰순위 필터를 걸지 않고** 전체 다운로드.

필요한 컬럼:
- `입찰공고번호` → project_id
- `개찰순위` → rank
- `투찰금액` → bid_amount
- `투찰율` → bid_rate (조달청이 직접 제공, 계산 불필요)

`bids_history`에 들어갈 정보(기초금액, 낙찰하한율 등)는 rank=1 행에서만 읽는다.
나머지 행은 `bid_participants`에만 저장한다.

## 향후 활용 계획

| 기능 | 설명 |
|------|------|
| **혼잡 구간 히트맵** | 발주처·공종별 투찰율 분포 시각화 |
| **동적 끝자리 블랙리스트** | 실제 데이터 기반으로 자주 겹치는 끝자리 자동 탐지 |
| **안전 구간 추천** | 과밀 구간을 피한 투찰가 후보 제안 |
| **1~2위 마진 분석** | 낙찰자와 탈락자 간 차이 → 최소 안전 마진 산출 |
