# 낙찰 투찰률 용어 및 계산식 정리

## 목표

프로젝트의 예측 목표를 `낙찰 투찰률`(낙찰가 ÷ 기초금액)로 명확히 하고, 데이터 모델·API·계산식·문서에서 기존의 `사정률`이라는 혼동되는 용어를 제거한다.

## 용어

| 용어 | 영문 식별자 | 정의 |
| --- | --- | --- |
| 낙찰 투찰률 | `winning_bid_rate` | 낙찰가 ÷ 기초금액 |
| 예측 낙찰 투찰률 | `predicted_winning_bid_rate` | 과거 낙찰 투찰률로부터 계산한 예측값 |
| 낙찰 투찰률 MAD | `winning_bid_rate_mad` | 예측 표본의 중앙 절대편차 |
| 예정가격 대비 투찰률 | `bid_rate` | 참여자 투찰가 ÷ 예정가격 |
| 기초금액 대비 투찰률 | `base_rate` | 참여자 투찰가 ÷ 기초금액 |
| 낙찰하한율 오프셋 | `lower_limit_offset` | 예정가격 대비 투찰률 − 낙찰하한율 |

`예정가격 ÷ 기초금액`은 이번 기능의 예측 대상이 아니다. 이후 필요해지면 `scheduled_price_rate`라는 별도 필드로 추가한다.

## 데이터 및 API 변경

1. `bids_history.adjustment_rate`를 `winning_bid_rate`로 마이그레이션한다. 기존 값은 낙찰가 ÷ 기초금액이므로 값 변환은 하지 않는다.
2. ORM, CRUD, fallback 함수 및 통계 함수의 변수명을 같은 의미로 갱신한다.
3. 계산 API의 응답은 `predicted_winning_bid_rate`, `winning_bid_rate_mad`, `predicted_winning_bid_rate_range`를 반환한다.
4. 기존 응답 필드는 호환성 유지를 위해 제공하지 않는다. 프론트엔드도 새 필드를 사용한다.

## 계산 규칙

예측 투찰가는 아래 식으로 계산한다.

```
추천 투찰가 = 기초금액 × 예측 낙찰 투찰률
```

따라서 계산 API에서는 낙찰하한율과 오프셋을 재곱하지 않는다. 낙찰하한율은 입찰 안전성 검증과 참여자 분포 분석에만 계속 사용한다.

## 검증

- 계산기가 `base_price × predicted_winning_bid_rate`를 반환하는 회귀 테스트를 먼저 추가한다.
- API 응답이 새 필드명을 반환하는 테스트를 추가한다.
- ETL 결과가 `winning_bid_rate = winner_price ÷ base_price`로 저장될 데이터를 생성하는 테스트를 추가한다.
- 전체 Python 테스트와 프론트엔드 타입 검사·빌드를 실행한다.

## 범위 제외

- 기존 DB 데이터의 자동 재적재
- 예정가격 또는 사정률 예측 기능
- 참여자 분포 엔진의 계산 로직 변경
