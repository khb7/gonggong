# 개발자 README 최신화 설계

## 목적

저장소 최상위 `README.md`를 현재 코드 기준의 개발자 온보딩 문서로 바꾼다. 새 개발자가 프로젝트의 목적, 구성, 로컬 실행 방법, 데이터 흐름, 검증 방법 및 운영상 제약을 한 곳에서 이해할 수 있어야 한다.

## 독자와 범위

- 독자: 이 저장소를 처음 다루는 개발자와 유지보수 담당자
- 범위: 최상위 `README.md`만 갱신한다.
- 기준: FastAPI 백엔드, React/Vite 프론트엔드, Alembic 마이그레이션, ETL·수집 스크립트 및 테스트에서 확인되는 현재 구현
- 제외: 제품 로드맵, 과거 진행률, 구현되지 않은 기능의 계획, 비밀 값이나 계정 정보

## 문서 구성

1. **개요**: 나라장터 공공입찰 이력과 참여자 데이터를 분석해 투찰가 계산과 경쟁자 분포 확인을 돕는 도구임을 설명한다. 사정률의 단정적 예측보다 과거 분포와 통계에 기반한 의사결정 지원이라는 현재 PRD의 방향을 따른다.
2. **주요 기능**: 투찰가 계산, 입찰별 오프셋 분포, 통계 조회, CSV 가져오기, 데이터 수집/스케줄러를 현재 제공 기능으로 나열한다.
3. **기술 구성과 디렉터리**: FastAPI, SQLAlchemy, Alembic, SQLite/PostgreSQL, React, Vite와 주요 디렉터리의 역할을 요약한다.
4. **빠른 시작**: 환경 변수 설정, Python/Node 의존성 설치, 마이그레이션, 백엔드와 프론트엔드 실행을 순서대로 제공한다. G2B API 키가 없으면 Mock fetcher를 사용하는 동작을 밝힌다.
5. **API와 화면**: 실제 라우트와 프론트 경로를 표로 요약한다. 요청·응답 전체 명세는 FastAPI의 OpenAPI 문서를 안내한다.
6. **데이터 흐름**: CSV 또는 수집 작업에서 DB 적재를 거쳐 분석 API와 UI로 가는 흐름을 설명하고, 관련 스크립트의 역할을 표시한다.
7. **검증과 제약**: `pytest`와 프론트 검사 명령을 제시하고, 외부 API/실데이터/DB 설정 의존성과 통계 결과의 해석상 한계를 명시한다.

## 정확성 원칙

- 현재 코드에 등록된 API와 화면만 문서화한다.
- 실제 인증 정보, API 키, 로그인 정보, 개인 키는 문서에 포함하지 않는다.
- 데이터 수집은 외부 서비스 접근과 실제 설정이 필요한 별도 운영 작업임을 구분한다.
- 정확한 성능 수치나 데이터 건수는 시점에 따라 달라지므로 고정 수치로 주장하지 않는다.

## 검증

- README에 적은 경로와 명령이 저장소의 실제 파일 및 설정과 일치하는지 점검한다.
- API·화면 목록을 백엔드 라우터와 React 라우팅 정의에 대조한다.
- 문서에서 비밀 정보와 구현되지 않은 약속이 없는지 확인한다.
